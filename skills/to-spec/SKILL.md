這個 skill 取用目前的對話情境與你對程式碼庫的理解，產出一份規格。**不要**訪談使用者；只需綜整你已經知道的內容。

議題追蹤系統與分流標籤詞彙應該已經提供給你。如果沒有，告訴使用者去執行 `/setup-matt-pocock-skills`。

## 流程

1. 如果還沒做過，先探索倉庫以理解程式碼庫目前的狀態。整份規格都要使用專案領域詞彙表中的詞彙，並尊重你所觸及區域內的任何 ADR。

2. 勾勒出你打算在哪些接縫（seams）測試這個功能。優先使用既有接縫，而不是新的。使用盡可能高的接縫。如果需要新的接縫，就在你能找到的最高點提出。整個程式碼庫的接縫越少越好，理想數量是一個。

向使用者確認這些接縫符合他們的預期。

3. 使用下方模板撰寫規格，然後發佈到專案的議題追蹤系統。套用 `ready-for-agent` 分流標籤：不需要再另外分流。

## 使用者故事

一份很長的、編號的使用者故事清單。每則使用者故事的格式如下：

1. 身為<角色>，我想要<功能>，以便<好處>

<user-story-example>
1. 身為行動銀行客戶，我想要查看各帳戶的餘額，以便對我的支出做出更明智的決定
</user-story-example>

這份使用者故事清單應該極為詳盡，涵蓋功能的所有面向。

## 實作決策

列出已做出的實作決策。可包含：

- 將要建置／修改的模組
- 將要修改的那些模組的介面
- 開發者的技術釐清
- 架構決策
- Schema 變更
- API 合約
- 特定的互動

**不要**包含具體的檔案路徑或程式碼片段。它們很快就可能過時。

例外：如果原型產生了一個片段，用它比用文字更精確地編碼了某個決策（狀態機、reducer、schema、型別形狀），就把它內嵌在相關決策中，並簡短註明它來自原型。只保留決策密度高的部分，不是可運作的 demo，只要重要的片段。
