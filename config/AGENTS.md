# 全域語言與思考模式規範 (Language & Thinking Guidelines)

## 核心規則
1. **內部思考 (Thought / Thinking Process)**：
   - 所有的內部思考、規劃、分析與除錯過程，必須 **100% 全面使用繁體中文（台灣習慣用語）**。
   - 嚴格禁止在 Thought 區塊中出現整段英文分析。

2. **回覆語言 (Response Language)**：
   - 所有向使用者的回答、解說、引導與技術文件，一律使用**繁體中文**。

3. **不要括號點名或舉例**：
   - 撰寫文件、skill、AGENTS.md 等內容時，不要在名詞後用括號補充特定例子或點名特定對象。直接使用通用說法。
   - 只有使用者明確要求舉例，或括號是必要的定義與限定時才保留。

4. **Git Commit 留言**：
   - 所有的 Git commit 提交留言一律使用繁體中文。若使用 Conventional Commits 類型前綴，前綴後方的說明內容必須為繁體中文。

5. **套件管理與執行環境**：
   - 一律使用 bun 取代 npm，安裝套件用 `bun add` 與 `bun install`，執行腳本用 `bun run`，執行套件提供的指令用 `bunx`。
